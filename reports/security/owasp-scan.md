- **目标项目**：`pixspring`（PixSpring · AI 文生图，Next.js 14 App Router + Vercel）
- **扫描方式**：针对源码的静态 + 逻辑层面人工审计（本环境镜像源不支持 `npm audit` 在线漏洞库查询，组件漏洞需在生产环境执行 `npm audit` 复核）

## A01：失效的访问控制（中危）

### 漏洞位置
- **文件**：`app/api/images/generations/route.ts`、`app/api/images/edits/route.ts`

### 漏洞分析
两个代理接口在收到任意请求时，直接使用服务端环境变量 `IMAGE_API_KEY` 调用上游付费接口，接口本身**没有任何调用方身份校验或访问凭证**。任何知道站点地址的人都可无限调用，从而消耗部署者的 API 额度。

### 复现步骤
```text
1. 打开部署后的站点域名（如 https://xxx.vercel.app）
2. 不登录、不携带任何凭证，直接 POST /api/images/generations
3. 接口正常返回 b64_json，部署者额度被消耗
```

### 影响
部署者额度被恶意/无限制消耗（资源消耗型滥用，非数据泄露）。

### 处理建议（部署侧）
- 在 Vercel 前置一层访问密码（如 `NEXT_PUBLIC_SITE_PASSWORD` 由服务端校验）；或
- 接入 Vercel 的速率限制 / WAF；或
- 仅以非公开 URL 形式自用，不对外推广。

## A02：加密失败（无风险）

- `IMAGE_API_KEY` 仅从 `process.env` 读取（`lib/image-api.ts`），未硬编码、未写入前端包。
- 调用上游 API 使用 HTTPS（TLS）。
- 错误处理中仅打印 `e?.message`，**未打印 API Key**（见 `route.ts` 的 `console.error("generate failed:", e?.message)`）。
- 结论：无加密失败类问题。

---

## A03：注入（无风险）

- 无 SQL / NoSQL / 命令 / LDAP / 表达式语言注入点。`prompt` 作为 JSON 字段或 `FormData` 字段原样转发给上游，未拼接到任何查询或 shell 命令。
- 服务端仅做 `fetch` 与数值 `clamp`/`Number` 转换，无可执行拼接。

---

## A04：不安全设计（中危）

与 A01 同源：缺少对付费上游调用的**限流（Rate Limiting）**。当前接口无并发/频次限制，单客户端可高频触发计费请求。

### 处理建议
- 服务端对单 IP 做短时间窗口限流（如 1 分钟最多 N 次），返回 `429`；
- 或依赖 Vercel 平台级限流能力。

---

## A05：安全配置错误（低危）

- 无默认凭据、无暴露管理面板。
- 错误响应会回传上游错误片段（已截断至 300 字符），属轻度信息泄露，但不含密钥。可接受；如需更严格可仅返回「上游服务异常」通用文案。

---

## A06：易受攻击和过时的组件（建议复核）

- 依赖均为较新稳定版本，且锁定于 `package.json`。
- **本环境镜像源不支持 `npm audit` 漏洞库查询**，未能自动比对 CVE。
- 建议：生产环境执行 `npm audit` 与 `npm outdated` 复核。

---

## A07：识别和认证失败（无风险）

- 产品定位为个人/小团队工具，无用户账户体系，故不存在弱密码、会话固定、凭据填充等场景。
- 若后续接入多用户，需补充认证与会话安全设计。

---

## A08：软件和数据完整性失败（无风险）

- 编辑接口接收上传图片仅作二进制转发，无反序列化执行；无自动更新机制；无远程加载未签名代码。

---

## A09：安全日志和监控失败（低危）

- 已对生成/编辑失败做 `console.error` 记录，但未记录调用来源 IP、频次与 prompt 长度，难以做滥用溯源与入侵检测。
- 建议：在不记录敏感内容前提下，补充记录来源 IP 与时间戳，便于配额异常的监控。

---

## A10：服务端请求伪造 SSRF（无风险）

- 服务端 `fetch` 的目标地址为硬编码常量（`lib/image-api.ts`），不接受任何用户可控的 URL 参数，不存在 SSRF。

---

## 总体结论

项目安全基线较扎实：**密钥隔离、HTTPS 传输、入参校验、无注入、无 SSRF** 均已满足。遗留的真实风险集中在 **A01/A04（代理接口缺访问控制与限流）**，属于资源滥用型问题，建议部署时通过访问密码或平台限流缓解。其余类别均为低危或不适用的设计层问题。
